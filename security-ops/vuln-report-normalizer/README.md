# 취약점 진단 결과 정규화 및 조치 가이드 생성

> 한 줄 요약: 형식이 제각각인 취약점 스캐너·모의해킹 결과를 하나로 합쳐 중복을 없애고, 실제 위험도로 우선순위를 매겨 개발자용 조치 가이드를 붙인다.

- 카테고리: security-ops
- 상태: 아이디어
- 작성일: 2026-10-27
- 구현 리포지터리: -

## 배경 / 문제

- SAST, DAST, SCA, 인프라 스캐너, 외부 모의해킹 보고서가 각기 다른 형식이라 통합 관리가 어렵다.
- 같은 취약점이 여러 도구에 중복 보고되고, 오탐이 많아 개발팀의 신뢰가 떨어진다.
- 개발자에게 "XSS 취약점 조치 바람"만 전달하면 실제 수정이 늦어진다.

## 목표

- 모든 결과를 공통 스키마로 정규화하고 중복을 묶는다.
- 자산 중요도, 외부 노출 여부, 코드 도달 가능성을 반영해 우선순위를 매긴다.
- 해당 코드 맥락에 맞는 언어·프레임워크별 수정 예시를 제공하고 이슈 트래커에 등록한다.

## 범위 밖 (Non-goals)

- 스캐너 자체 개발.

## 사용자 / 사용 시나리오

1. 담당자가 스캐너 결과(SARIF, JSON, xml)나 모의해킹 보고서(pdf)를 업로드한다.
2. 도구가 정규화·중복 제거·오탐 후보 표시를 한다.
3. 확정된 항목은 담당 개발팀 리포지터리 이슈로 등록되며, 수정 예시 코드가 포함된다.
4. 조치 기한(SLA)과 재점검 결과를 추적한다.

## 핵심 기능

- [ ] 입력 파서 (SARIF, 주요 스캐너 포맷, pdf 보고서는 AI 추출)
- [ ] 공통 스키마(CWE, 위치, 심각도, 자산) 정규화와 중복 병합
- [ ] 소스 코드 맥락을 읽어 도달 가능성·오탐 판단 보조
- [ ] 조치 가이드와 수정 예시 생성
- [ ] 이슈 트래커 연동, SLA 대시보드

## 기술 구상

- 저장: 취약점 DB(DefectDojo 연동 또는 자체)
- AI: Claude API로 보고서 추출, 코드 맥락 분석, 수정안 생성
- 연동: GitHub/GitLab/Jira 이슈 API

## 구현 단계 (MVP → 확장)

1. MVP: SARIF 여러 개 병합 + 중복 제거 + 조치 가이드 보고서.
2. pdf 모의해킹 보고서 추출, 이슈 자동 등록.
3. 코드 도달 가능성 분석, 수정 PR 자동 제안.

## 열린 질문 / 리스크

- 오탐 판정 책임과 승인 절차.
