# 피싱 신고 메일 자동 분석

> 한 줄 요약: 직원이 신고한 의심 메일의 헤더·링크·첨부를 자동 분석해 판정하고, 같은 메일을 받은 수신자 일괄 조치와 신고자 회신까지 처리한다.

- 카테고리: security-ops
- 상태: 아이디어
- 작성일: 2026-10-27
- 구현 리포지터리: -

## 배경 / 문제

- 피싱 신고가 많아질수록 보안팀이 메일을 하나씩 열어 헤더와 링크를 확인하는 부담이 커진다.
- 신고자에게 결과를 알려주지 못해 신고 문화가 약해진다.

## 목표

- 신고 메일을 자동 분석해 정상 / 스팸 / 피싱 / 악성으로 판정한다.
- 피싱이면 동일 메일 수신자 검색과 일괄 삭제를 제안한다.
- 신고자에게 결과와 짧은 교육 메시지를 회신한다.

## 범위 밖 (Non-goals)

- 메일 게이트웨이 대체.

## 사용자 / 사용 시나리오

1. 직원이 "피싱 신고" 버튼이나 전용 주소로 메일을 전달한다.
2. 도구가 SPF/DKIM/DMARC 결과, 발신 도메인 나이, 링크 리디렉션 경로, 첨부 해시 평판, 본문 사회공학 패턴을 분석한다.
3. AI가 판정과 근거를 정리해 보안팀에 보고하고, 피싱이면 같은 메일 수신자 목록을 보여준다.
4. 신고자는 "신고 감사합니다. 이 메일은 ○○ 이유로 피싱입니다" 회신을 받는다.

## 핵심 기능

- [ ] 신고 메일 수집(전용 메일함, 원본 eml 보존)
- [ ] 헤더·링크·첨부 분석 (샌드박스 URL 스캔 연동)
- [ ] AI 판정과 근거 요약
- [ ] 동일 캠페인 수신자 검색·일괄 삭제(승인 후)
- [ ] 신고자 자동 회신, 통계 대시보드

## 기술 구상

- 메일: Microsoft Graph API 또는 Google Workspace API
- 분석: urlscan.io, VirusTotal 등 API
- AI: Claude API로 본문 사회공학 분석, 판정 설명

## 구현 단계 (MVP → 확장)

1. MVP: 신고 메일 분석 보고서를 보안팀에 전달.
2. 신고자 자동 회신, 동일 메일 검색.
3. 승인 기반 일괄 삭제, 모의 훈련 메일 자동 구분.

## 열린 질문 / 리스크

- 메일 본문 열람 권한과 개인정보 처리 근거.
- 링크 자동 접속 시 추적 토큰 활성화 위험 → 격리 환경에서 접속.
