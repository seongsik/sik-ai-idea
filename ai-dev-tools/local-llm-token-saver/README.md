# 로컬 LLM 토큰 절감 도구 (Claude Code·Codex 공용)

> 한 줄 요약: 애플 실리콘 맥(32GB)의 로컬 LLM에 요약, 검색, 단순 작업을 맡기고 토큰이 어디에 쓰이는지 측정해, Claude Code와 Codex에서 공통으로 클라우드 토큰 사용량을 줄이는 도구

- 카테고리: ai-dev-tools
- 상태: 아이디어
- 작성일: 2026-11-13
- 구현 리포지터리: 없음

## 배경 / 문제

- 에이전트 코딩(Claude Code, Codex)을 API 종량제로 쓰는데, 토큰 상한에 금방 도달한다.
- 컨텍스트 압축 도구 Headroom을 써 봤지만 체감 효과가 적었다. 알려진 한계는 다음과 같다.
  - 셸 출력 압축 훅은 Bash 도구 호출에만 적용된다. Claude Code의 Read, Grep, Glob 같은 기본 도구 출력은 압축되지 않는다.
  - 코드는 별도 설정(AST 압축)을 켜지 않으면 그대로 넘어간다. 코딩 세션의 입력은 대부분 코드다.
  - 200토큰 미만의 짧은 출력은 그대로 통과한다.
  - 광고하는 절감률(60~95%)은 로그가 많은 경우의 최대치다. 일반 세션의 실측 사례는 15~35% 수준이다.
- 더 근본적으로는 **토큰이 실제로 어디에 쓰이는지 모른 채** 도구를 붙였다. 파일 읽기, 도구 출력, 대화 이력 재전송, 생각 토큰과 출력 중 무엇이 상한을 채우는지 알아야 맞는 대책을 고를 수 있다.
- 맥(애플 실리콘, 메모리 32GB)의 GPU와 신경망 코어가 개발 중에 거의 놀고 있다.

## 목표

- 세션의 토큰 사용을 항목별로 측정해, 상한을 채우는 주된 원인을 보여 준다.
- 판단이 적고 토큰이 많이 드는 일(큰 출력 요약, 코드 검색, 단순 작성)을 로컬 LLM으로 넘겨 클라우드 입력 토큰을 줄인다.
- Claude Code와 Codex 양쪽에서 같은 도구를 같은 방식으로 쓴다.
- 작업 품질(작업 완료율, 재시도 횟수)이 떨어지지 않는 범위에서만 절감한다. 토큰이 줄어도 재시도가 늘면 실패로 본다.

## 범위 밖 (Non-goals)

- 메인 에이전트 자체를 로컬 모델로 바꾸는 것. 32GB 메모리로 돌릴 수 있는 모델은 여러 단계를 이어 가는 에이전트 작업에서 클라우드 최상위 모델보다 확실히 약하다.
- 월정액 요금제 최적화. 대상은 종량제 API 사용이다.
- 특정 IDE 플러그인. 터미널 에이전트(Claude Code, Codex CLI)를 기준으로 한다.

## 사용자 / 사용 시나리오

사용자는 본인 한 명이다. 32GB 애플 실리콘 맥에서 Claude Code와 Codex를 종량제 API로 쓴다.

1. **진단:** 일주일 동안 측정 모드로 쓴 뒤 보고서를 본다. 예: "입력의 45%가 파일 전체 읽기, 25%가 테스트 로그, 이력 재전송은 캐시로 대부분 처리됨, 생각 토큰이 출력의 70%".
2. **로그 요약:** 테스트가 실패해 3만 줄 로그가 나오면, 로컬 모델이 실패 테스트 이름, 오류 메시지, 관련 스택 몇 줄만 추려서 에이전트에게 넘긴다. 원문은 로컬에 보관하고, 필요하면 에이전트가 특정 부분을 다시 요청한다.
3. **코드 검색:** 에이전트가 "결제 검증 로직 어디 있어?"를 찾을 때, 파일을 하나씩 통째로 읽는 대신 로컬 검색 도구가 관련 함수 정의와 위치만 돌려준다.
4. **단순 작업 위임:** 커밋 메시지, 변경 요약, 반복적인 이름 변경 같은 일은 로컬 모델이 초안을 만들고, 메인 에이전트는 검토만 한다.
5. **효과 확인:** 도구를 켠 주와 끈 주의 토큰 사용량과 작업 완료율을 비교한다.

## 핵심 기능

### 1. 토큰 측정 (먼저 만든다)

- [ ] 세션 기록에서 토큰을 항목별로 나눈다: 시스템 프롬프트와 도구 정의, 파일 읽기, 검색 결과, 셸 출력, 대화 이력 재전송(캐시 적중과 미적중), 생각 토큰, 출력.
  - Claude Code는 로컬 세션 기록(JSONL), Codex는 세션 로그를 읽는다. 둘 다 없으면 아래 게이트웨이에서 측정한다.
- [ ] 상한을 채우는 상위 원인과 그에 맞는 대책을 추천한다. 예: 캐시 적중률이 낮으면 캐시 깨짐 원인부터, 생각 토큰이 크면 추론 수준(effort) 조정부터.
- [ ] 도구 적용 전후 비교 보고서.

### 2. 로컬 LLM 도구 (MCP 서버)

Claude Code와 Codex 모두 MCP를 지원하므로, 공통 기능은 MCP 서버 하나로 제공한다.

- [ ] `summarize_output`: 긴 셸 출력, 로그, 큰 파일을 목적에 맞게 요약한다(예: "실패 원인만", "이 함수와 관련된 부분만"). 원문은 로컬에 저장하고 ID를 함께 돌려준다.
- [ ] `retrieve_original`: 요약 전 원문에서 특정 줄 범위나 키워드 주변을 가져온다. 요약 때문에 정보가 빠졌을 때 쓰는 탈출구다.
- [ ] `search_code`: 로컬 임베딩과 언어 서버(LSP)로 만든 코드 색인에서, 관련 심볼의 정의와 위치만 돌려준다.
- [ ] `draft`: 커밋 메시지, 변경 요약, 단순 반복 수정안의 초안을 로컬 모델로 만든다.
- [ ] `stats`: 도구별로 줄인 토큰 수와 원문 재요청 비율.

### 3. 에이전트 지침 파일

- [ ] Claude Code용 `CLAUDE.md`와 Codex용 `AGENTS.md`에 같은 규칙을 넣는 설치 스크립트. 예: "출력이 N줄을 넘을 것 같은 명령은 summarize_output을 거쳐라", "파일 전체를 읽기 전에 search_code를 먼저 써라".
- [ ] 규칙의 문턱값(N줄 등)을 측정 결과로 조정한다.

### 4. 게이트웨이 (선택, 2단계)

에이전트와 클라우드 API 사이의 로컬 프록시다. 에이전트가 MCP 도구를 쓰지 않아도 적용된다.

- [ ] Anthropic Messages API와 OpenAI Responses API를 모두 받는다.
- [ ] **새로 추가되는 도구 결과(tool_result)만** 문턱값을 넘으면 압축한다. Headroom 훅이 놓치는 Read, Grep 결과도 여기서 처리된다.
- [ ] 이미 보낸 대화 이력은 절대 바꾸지 않는다(아래 "캐시와 이력 보존" 참고).
- [ ] 요청별 토큰 측정과 기록.

## 기술 구상

- 기술 스택: Python 또는 TypeScript. 로컬 추론은 MLX(애플 실리콘 전용 엔진) 또는 Ollama, LM Studio. 코드 색인은 tree-sitter, 언어 서버, 로컬 임베딩 모델, SQLite.
- 로컬 모델 (32GB 기준, 제안값):

| 용도 | 모델 규모 | 메모리 | 이유 |
|---|---|---|---|
| 요약, 초안 | 4B~8B급 | 약 3~6GB | 긴 입력을 처음 읽는 단계(prefill)가 빨라야 함. 큰 모델은 3만 토큰 로그 요약에 수십 초가 걸려 에이전트 흐름이 끊김 |
| 어려운 요약 (선택) | 30B급 MoE (예: Qwen3-Coder 30B-A3B, 4비트) | 약 17GB | 필요할 때만 불러옴. 상시 띄우면 IDE, 브라우저, 빌드에 쓸 메모리가 부족 |
| 코드 검색 | 소형 임베딩 모델 | 1GB 미만 | 색인과 검색 |

- 상시 메모리 사용은 8GB 이내로 제한한다. 나머지는 개발 환경에 남긴다.

### 캐시와 이력 보존 (중요)

- 클라우드 API는 앞부분이 같은 요청을 캐시해 싸게 처리한다(캐시 읽기는 입력 요금의 약 5~10%). **이미 보낸 이력을 압축하거나 고치면 그 뒤 캐시가 전부 깨져서 오히려 비용이 늘어난다.**
- 최신 Claude 모델은 이전 턴을 수정하면 생각(thinking) 블록도 무효가 된다. 일부 계정은 요청이 거부된다.
- 그래서 압축은 **처음 보낼 때 한 번만**, 같은 입력에 항상 같은 결과가 나오게(결정적으로) 한다. 요약 결과는 원문 해시 기준으로 저장해 재사용한다.
- 측정 기능으로 캐시 적중률을 계속 확인한다. 도구를 켠 뒤 적중률이 떨어지면 경보를 낸다.

### 아키텍처

1. **측정기:** 세션 기록 또는 게이트웨이 로그를 읽어 항목별 토큰 보고서를 만든다.
2. **MCP 서버:** 요약, 원문 조회, 코드 검색, 초안, 통계 도구.
3. **로컬 추론 서버:** MLX 또는 Ollama. 모델 적재와 해제를 관리한다.
4. **원문 저장소:** 요약 전 원문과 요약 결과를 해시로 저장한다.
5. **게이트웨이 (2단계):** Anthropic, OpenAI 형식 프록시. 새 도구 결과 압축과 측정.

## 구현 단계 (MVP → 확장)

1. **측정기:** Claude Code와 Codex 세션 기록 분석, 항목별 토큰 보고서. 이 결과로 2~4단계의 우선순위를 정한다.
2. **MCP 요약 도구:** summarize_output, retrieve_original, stats. 소형 로컬 모델. CLAUDE.md, AGENTS.md 지침 설치.
3. **코드 검색:** search_code(LSP와 임베딩 색인).
4. **비교 실험:** 같은 종류의 작업을 도구를 켜고 끄고 해서 토큰, 완료율, 재시도 횟수, 소요 시간을 비교한다.
5. **게이트웨이:** 지침만으로 효과가 부족하면 프록시로 강제 적용한다.
6. **확장:** draft 도구, 측정 결과 기반 문턱값 자동 조정.

## 열린 질문 / 리스크

- 에이전트가 MCP 도구를 지침대로 쓰지 않을 수 있다. 실제 사용률을 측정하고, 낮으면 게이트웨이로 강제한다.
- 요약에서 중요한 정보가 빠지면 에이전트가 잘못 판단하거나 재시도한다. 원문 재요청 비율과 재시도 횟수를 품질 지표로 본다.
- 로컬 추론이 느리면 개발 흐름이 끊긴다. 요약 한 건당 목표 시간(예: 10초 이내)을 두고 넘으면 더 작은 모델로 내리거나 원문을 그대로 보낸다.
- 측정 결과 상한의 주원인이 로컬 LLM으로 줄일 수 없는 것(생각 토큰, 출력)일 수 있다. 그 경우 추론 수준 조정, 세션 정리 습관, 서브에이전트 활용 같은 비(非)LLM 대책을 먼저 권한다.
- Claude Code와 Codex의 세션 기록 형식은 버전마다 바뀔 수 있다. 파서를 분리해 두고 버전별로 테스트한다.
- 게이트웨이에 API 키가 지나가므로 로컬에서만 동작하게 하고(localhost 바인딩), 로그에 키와 비밀값을 남기지 않는다.
