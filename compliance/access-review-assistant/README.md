# 계정·권한 정기 검토 보조

> 한 줄 요약: 인사 데이터와 각 시스템의 계정·권한 목록을 대조해 퇴사자·부서이동자·장기 미사용 계정과 과다 권한을 찾고, 부서장 확인 요청까지 자동화한다.

- 카테고리: compliance
- 상태: 아이디어
- 작성일: 2026-10-27
- 구현 리포지터리: -

## 배경 / 문제

- 개인정보처리시스템 접근권한은 인사이동 시 지체 없이 변경·말소해야 하고, 정기 검토 기록이 ISMS-P 증적으로 요구된다.
- 시스템마다 계정 목록 형식이 달라 엑셀로 수작업 대조하며, 부서장 확인 회신을 받는 데 시간이 많이 든다.

## 목표

- 시스템별 계정·권한 목록을 정규화해 인사 데이터와 자동 대조한다.
- 이상 계정 목록과 부서장별 확인 요청서를 자동 생성·발송하고 회신을 집계한다.

## 범위 밖 (Non-goals)

- 계정 자동 삭제·권한 회수 실행 (승인 후 담당자 처리 또는 별도 IAM 연동).

## 사용자 / 사용 시나리오

1. 담당자가 시스템별 계정 목록(csv/xlsx 또는 API)과 인사 데이터를 등록한다.
2. 도구가 퇴사자 계정, 부서이동 후 잔존 권한, N일 미사용 계정, 공용 계정, 관리자 권한 보유자를 표시한다.
3. 부서장에게 소속 직원의 권한 목록을 보내 유지/회수 의견을 받는다.
4. 결과를 검토 기록으로 보관한다.

## 핵심 기능

- [ ] 계정 목록 업로드/수집과 형식 정규화 (AI가 컬럼 의미 자동 매핑)
- [ ] 인사 데이터 대조 규칙과 이상 계정 탐지
- [ ] 역할 대비 과다 권한 추정 (같은 직무 대비 이례적 권한)
- [ ] 부서장 확인 요청 메일/폼, 회신 집계
- [ ] 검토 결과 보고서(증적)

## 기술 구상

- 데이터 처리: Python(pandas), 이름·사번 퍼지 매칭
- AI: 컬럼 매핑, 이상 권한 설명 문장 생성
- 발송: 메일 또는 사내 메신저

## 구현 단계 (MVP → 확장)

1. MVP: 엑셀 2개(인사, 계정) 업로드 → 이상 계정 목록.
2. 다중 시스템, 부서장 확인 워크플로.
3. 주요 시스템 API 연동(AD/Entra ID, SaaS 관리 API).

## 열린 질문 / 리스크

- 인사 데이터 취급 권한과 보관 기간.
- 동명이인·사번 없는 외주 인력 매칭.

## 참고 자료

- 개인정보의 안전성 확보조치 기준 (접근권한 관리)
