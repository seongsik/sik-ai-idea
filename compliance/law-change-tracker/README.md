# 법령 변경 추적 및 사내 규정 신구대조표 자동 작성

> 한 줄 요약: 법령정보 API로 보안·개인정보 관련 법령의 개정을 감지하고, 영향받는 사내 규정 조항을 찾아 개정안과 신구대조표를 자동으로 만든다.

- 카테고리: compliance
- 상태: 아이디어
- 작성일: 2026-10-27
- 구현 리포지터리: -

## 배경 / 문제

- 보안팀은 개인정보 보호법, 정보통신망법, 전자금융거래법, 전자문서법 등 여러 법령과 그 시행령·시행규칙, 고시(개인정보의 안전성 확보조치 기준 등)를 지켜야 한다.
- 개정 사실을 뉴스나 공문으로 뒤늦게 알게 되는 경우가 많고, 사내 규정(정보보호 정책, 개인정보 내부관리계획, 지침 등)의 어느 조항에 영향을 주는지 사람이 일일이 대조해야 한다.
- 규정을 개정할 때 결재용 신구대조표를 표로 수작업 작성하며, 법령 근거 조문 번호가 바뀌는 등 단순 변경도 누락되기 쉽다.
- ISMS-P 심사에서 "법적 요구사항 변경을 주기적으로 검토하고 반영하는지"(1.1 관리체계 기반 마련, 2.x 법적 요구사항 준수 검토)에 대한 증적이 필요하다.

## 목표

- 관심 법령의 개정(공포, 시행 예정, 시행)을 매일 자동 감지한다.
- 변경 조문과 사내 규정 조항 간 영향 관계를 AI가 분석해 제시한다.
- 사내 규정 개정안 초안과 결재용 신구대조표(현행/개정안/비고)를 자동 생성한다.
- 검토 이력을 남겨 ISMS-P 법적 요구사항 검토 증적으로 활용한다.

## 범위 밖 (Non-goals)

- 법률 자문 대체. AI 결과는 초안이며 최종 판단은 담당자·법무 검토를 거친다.
- 사내 결재 시스템 자체 개발 (산출물 파일을 결재에 첨부하는 수준까지).

## 사용자 / 사용 시나리오

1. 보안 담당자가 추적할 법령·행정규칙 목록과 사내 규정 문서를 등록한다.
2. 매일 아침 배치가 법령 API를 조회해 개정 사항을 감지하면 메일/메신저로 알린다. ("개인정보 보호법 시행령 일부개정 공포, 시행일 2027-03-15, 변경 조문 5개, 영향 사내 규정 3개 조항")
3. 담당자가 알림을 열면 법령 신구조문과 함께 "영향받는 사내 규정 조항 + 수정 필요 여부 + 근거"가 보인다.
4. 담당자가 반영할 항목을 선택하면 사내 규정 개정안과 신구대조표(docx/xlsx/hwp 호환)가 생성된다.
5. 개정 완료 후 처리 결과(반영/미반영 사유)를 기록하면 법적 요구사항 검토 대장에 누적된다.

## 핵심 기능

- [ ] 법령 추적 목록 관리 (법령, 시행령, 시행규칙, 행정규칙/고시)
- [ ] 법령 변경 감지: 공포일·시행일·개정 구분(일부개정/전부개정/타법개정) 수집
- [ ] 법령 신구조문 비교 수집 (API 제공 신구법 비교 활용, 없으면 연혁 본문 diff)
- [ ] 사내 규정 문서 파싱: 장·조·항·호 단위 구조화, 법령 인용 조문 추출
- [ ] 영향 분석: (1) 인용 조문 번호 직접 매칭 (2) 의미 유사도 기반 후보 검색 (3) LLM이 수정 필요 여부와 이유 판단
- [ ] 개정안 초안 생성: 원문 문체·조항 체계를 유지한 최소 수정
- [ ] 신구대조표 생성: 현행 | 개정안 | 비고(근거 법령 조문), 변경 부분 밑줄/강조
- [ ] 알림: 메일, 사내 메신저(Slack/Teams 등) 웹훅
- [ ] 법적 요구사항 검토 대장(이력) 및 내보내기

## 기술 구상

- 데이터 소스: 국가법령정보센터 Open API (open.law.go.kr) — 법령 목록/본문, 법령 연혁, 신구법 비교, 행정규칙 조회. API 키(OC) 발급 필요.
- 변경 감지: 추적 법령별 최신 법령일련번호(MST)·공포일·시행일을 저장해 두고 매일 비교. 시행 예정 법령도 별도 상태로 관리.
- 사내 규정 저장: 원본(docx/hwp/pdf) → 조항 단위 JSON으로 정규화 → 벡터 인덱스.
- AI: Claude API로 영향 판단, 개정안 초안, 비고 작성. 판단마다 근거 조문 인용을 강제하고, 근거 없는 판단은 "검토 필요"로 분류.
- 산출물: 신구대조표 docx(표), xlsx. 사내 표준이 HWP라면 hwpx 템플릿 채우기 검토.
- 실행 형태: 일 1회 배치(스케줄러) + 간단한 웹 UI 또는 메신저 봇.

```
[법령 API] → 변경 감지 → 신구조문 수집 ─┐
                                      ├→ 영향 분석(LLM) → 개정안 초안 → 신구대조표
[사내 규정] → 조항 파싱 → 인덱스 ────────┘                     ↓
                                                    알림 / 검토 대장
```

## 구현 단계 (MVP → 확장)

1. MVP: 법령 5~10개 추적, 변경 감지 및 법령 신구조문 메일 알림.
2. 사내 규정 1~2개(예: 개인정보 내부관리계획) 연결, 인용 조문 번호 기반 영향 조항 표시.
3. LLM 영향 분석 + 개정안 초안 + 신구대조표 docx 생성.
4. 행정규칙/고시, 입법예고(시행 전 사전 대응)까지 확대. 검토 대장과 ISMS-P 증적 연계.

## 열린 질문 / 리스크

- 법령정보 API의 신구법 비교 제공 범위(행정규칙·고시 포함 여부)와 호출 제한 확인 필요.
- 사내 규정 원본 형식(HWP 비중)에 따른 파싱 난이도.
- 타법개정으로 인한 조문 번호 이동 같은 간접 변경을 놓치지 않는 방법.
- 입법예고 단계 정보(국민참여입법센터) 수집 가능 여부.
- AI 판단 오류 책임: 반드시 사람 승인 단계를 둔다.
