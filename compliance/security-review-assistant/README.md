# 보안성 검토 1차 리뷰어

> 한 줄 요약: 신규 시스템·외부 SaaS 도입·개발 변경 요청 문서를 AI가 보안 체크리스트로 1차 검토하고, 부족한 점과 요청자에게 보낼 질문 목록을 만든다.

- 카테고리: compliance
- 상태: 아이디어
- 작성일: 2026-10-27
- 구현 리포지터리: -

## 배경 / 문제

- 보안성 검토 요청은 많은데 검토 인력은 적어 대기 시간이 길다.
- 요청서에 필요한 정보(데이터 흐름, 개인정보 항목, 인증 방식, 위탁 여부)가 빠져 있는 경우가 많아 질문-답변 왕복이 반복된다.
- 검토 기준이 담당자마다 달라 일관성이 떨어진다.

## 목표

- 요청 접수 즉시 1차 검토 결과(충족/미흡/정보 부족)를 제공해 왕복 횟수를 줄인다.
- 사내 보안성 검토 체크리스트를 기준으로 일관된 판단 근거를 남긴다.

## 범위 밖 (Non-goals)

- 최종 승인 결정. 보안 담당자가 검토 후 확정한다.

## 사용자 / 사용 시나리오

1. 요청자가 설계서, 아키텍처 다이어그램, SaaS 소개 자료, 보안 인증서(ISO 27001, SOC 2 등)를 첨부해 요청한다.
2. AI가 체크리스트 항목별로 문서에서 근거를 찾아 판정하고, 근거가 없으면 질문을 생성한다.
3. 요청자는 질문에 답하고, 보안 담당자는 정리된 결과를 보고 승인/조건부 승인/반려한다.

## 핵심 기능

- [ ] 사내 체크리스트 관리 (인증·접근통제, 암호화, 개인정보 처리, 로깅, 위탁·국외이전, 취약점 점검, 백업 등)
- [ ] 첨부 문서 파싱(pdf, docx, pptx, 이미지)과 항목별 근거 인용
- [ ] 정보 부족 항목에 대한 질문 자동 생성
- [ ] SaaS의 경우 공개 정보(보안 페이지, 개인정보 처리방침, 인증 현황) 웹 조사
- [ ] 검토 결과 보고서 및 조건부 승인 조건 초안

## 기술 구상

- 접수: 티켓 시스템(Jira 등) 웹훅 또는 메일
- AI: Claude API, 항목별 구조화 출력(판정, 근거 인용, 질문)
- 결과를 티켓 코멘트로 작성

## 구현 단계 (MVP → 확장)

1. MVP: 문서 업로드 → 체크리스트 판정 보고서.
2. 티켓 시스템 연동, 질문-답변 루프.
3. SaaS 공개 정보 자동 조사, 과거 검토 이력 검색(유사 사례 참고).

## 열린 질문 / 리스크

- 기밀 설계 문서를 외부 AI API로 보낼 때의 사내 정책 확인.
- 체크리스트 버전 관리와 판정 기준 문서화.
