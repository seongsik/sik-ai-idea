# 개인정보 처리방침-실제 수집 정합성 점검

> 한 줄 요약: 웹사이트의 개인정보 처리방침과 실제 입력 폼·쿠키·제3자 스크립트를 브라우저 탐색으로 비교해 고지되지 않은 수집·제공·국외이전을 찾는다.

- 카테고리: compliance
- 상태: 아이디어
- 작성일: 2026-10-27
- 구현 리포지터리: -

## 배경 / 문제

- 처리방침은 법무/보안팀이 관리하고, 실제 서비스 화면과 마케팅 태그는 개발·마케팅팀이 바꾸기 때문에 둘이 쉽게 어긋난다.
- 분석·광고 태그(GA, 메타 픽셀 등)가 추가되면서 고지하지 않은 제3자 제공이나 국외이전이 생길 수 있다.
- 개인정보 보호법상 처리방침 미기재·불일치는 과태료 대상이며 점검이 수작업이다.

## 목표

- 대상 사이트를 브라우저로 탐색해 실제 수집 항목, 쿠키, 외부 전송 도메인을 자동 수집한다.
- 처리방침 문서의 고지 항목과 비교해 불일치 목록과 수정 제안을 보고서로 만든다.

## 범위 밖 (Non-goals)

- 백엔드 내부 처리(DB 저장, 내부 시스템 간 전송) 점검.

## 사용자 / 사용 시나리오

1. 점검 대상 URL과 시나리오(회원가입, 주문, 문의)를 등록한다.
2. 브라우저 에이전트가 시나리오대로 탐색하며 폼 필드, 쿠키, 네트워크 요청(외부 도메인)을 기록한다.
3. AI가 처리방침을 구조화(수집 항목, 목적, 보유기간, 제3자 제공, 위탁, 국외이전)하고 실측 결과와 비교한다.
4. "고지 누락 / 과다 고지 / 확인 필요" 보고서와 처리방침 수정 문구 초안을 받는다.

## 핵심 기능

- [ ] 시나리오 기반 브라우저 탐색과 폼 필드·쿠키·네트워크 요청 수집
- [ ] 외부 도메인 → 업체·국가 식별 (서드파티 태그 DB)
- [ ] 처리방침 구조화 추출
- [ ] 비교 결과 보고서, 처리방침 수정 문구 초안
- [ ] 정기 점검과 변경 감지(새 태그 추가 알림)

## 기술 구상

- 브라우저: Playwright 또는 Claude 브라우저 탐색 기능, HAR 수집
- AI: Claude API로 처리방침 구조화 및 비교 판단
- 보고서: html/docx

## 구현 단계 (MVP → 확장)

1. MVP: 단일 페이지의 쿠키·외부 요청 수집 + 처리방침 비교.
2. 다단계 시나리오(가입·주문) 지원.
3. 정기 점검과 변경 알림, 여러 사이트 관리.

## 열린 질문 / 리스크

- 테스트 계정, 결제 단계 등 실제 데이터 입력이 필요한 시나리오 처리.
- 동의 배너 선택에 따른 동작 차이(동의 전 전송 여부) 점검 방법.
