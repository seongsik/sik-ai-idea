# 백신·EDR 엔진

> 한 줄 요약: 단말에서 악성코드를 탐지하고 행위를 기록·대응하는 백신·EDR 엔진을, 탐지 시그니처·행위 룰 생성과 악성코드 분석 보고서 작성을 AI로 자동화해 개발·운영한다.

- 카테고리: security-solution
- 영역: ENDPOINT (단말 안에서 동작)
- 사내 개발 경험: 있음 (현업에서 직접 개발한 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 신종 악성코드 샘플이 매일 쌓이지만, 분석·시그니처 작성 인력이 부족하다.
- 행위 기반 탐지 룰(프로세스 생성, 레지스트리, 네트워크)은 오탐 조정에 시간이 많이 든다.
- OS 업데이트마다 커널 드라이버·후킹 모듈의 호환성 테스트가 필요하다.

## 목표

- 샘플을 넣으면 정적·동적 분석 결과를 모아 AI가 분석 보고서와 YARA·행위 룰 초안을 만든다.
- 정상 소프트웨어 코퍼스로 오탐을 자동 측정한 뒤 배포한다.
- OS·드라이버 호환성 테스트를 자동화한다.

## 범위 밖 (Non-goals)

- AI 모델 단독으로 악성 판정해 자동 삭제하는 것 (판정 근거 없는 삭제 금지).
- 악성코드 생성·변형 실험.

## 사용자 / 사용 시나리오

1. 분석가가 수집된 샘플을 분석 파이프라인에 넣는다.
2. 샌드박스 동적 분석과 정적 분석(문자열, 임포트, 패킹) 결과가 모인다.
3. AI가 행위 요약, ATT&CK 기법 매핑, YARA·행위 룰 초안을 만든다.
4. 오탐 테스트를 통과하면 분석가 승인 후 엔진 업데이트로 배포된다.
5. 단말 EDR 에이전트는 행위 이벤트를 수집해 서버로 보내고, 관제 요원이 사건 타임라인을 본다.

## 핵심 기능

- [ ] 시그니처·해시·YARA 기반 정적 탐지
- [ ] 행위 이벤트 수집(프로세스·파일·레지스트리·네트워크)과 행위 룰 탐지
- [ ] 샘플 분석 자동화 파이프라인과 AI 분석 보고서
- [ ] 룰 오탐 자동 측정(정상 코퍼스)
- [ ] 격리·프로세스 종료·네트워크 차단 대응
- [ ] 사건 타임라인 조회

## 기술 구상

- 기술 스택: C/C++(Windows 미니필터·ETW, Linux eBPF), Rust(에이전트 사용자 영역), Go(서버), ClickHouse/Elasticsearch(이벤트)
- 아키텍처: 에이전트(탐지 엔진 + 이벤트 수집) → 수집 서버 → 분석·룰 엔진 → 콘솔 / 별도 분석 파이프라인(샌드박스 → AI 분석 → 룰 저장소)
- 외부 연동: 샌드박스(CAPE 등), VirusTotal, 위협 인텔, SIEM
- AI 자동 개발 적용점:
  - 룰 생성: 분석 결과 → YARA·Sigma 형식 행위 룰 초안
  - 보고서: 동적 분석 로그 → 사람이 읽는 분석 보고서
  - 테스트: OS 버전 매트릭스 호환성 테스트 시나리오 생성

## 구현 단계 (MVP → 확장)

1. MVP: 샘플 분석 파이프라인 + AI 보고서·YARA 초안 + 오탐 측정.
2. 행위 룰 자동 생성, 에이전트 이벤트 수집 확대, 사건 타임라인.
3. 자동 대응 플레이북, 위협 헌팅 질의(자연어 → 이벤트 검색).

## 열린 질문 / 리스크

- 커널 모듈 코드를 AI로 생성할 때의 안정성(블루스크린) → 커널 영역은 사람 리뷰 필수.
- 악성 샘플 취급 환경 격리.
- 기존 사내 엔진과 룰 포맷 호환.
