# 인증·PKI·MFA

> 한 줄 요약: 사내 시스템의 통합 인증(SSO), 다중 인증(MFA), 인증서(PKI) 발급·관리를 제공하는 솔루션을, 표준 프로토콜 구현과 연동 커넥터를 AI로 자동 개발해 만든다.

- 카테고리: security-solution
- 영역: ACCESS (사람과 권한을 통제)
- 사내 개발 경험: 없음 (신규 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 사내·고객사 레거시 시스템은 자체 로그인을 쓰고 있어 SSO·MFA 적용에 시스템별 연동 개발이 필요하다.
- 내부 인증서(서버 TLS, 기기 인증서)가 수작업으로 관리돼 만료 장애가 난다.
- 패스키(FIDO2) 등 비밀번호 없는 인증 요구가 늘고 있다.

## 목표

- OIDC·SAML 기반 SSO와 OTP·푸시·FIDO2 MFA를 제공한다.
- 레거시 시스템 연동 커넥터(로그인 화면 대리 입력, 헤더 기반, 에이전트)를 AI로 생성·테스트한다.
- 사설 CA와 인증서 자동 발급·갱신(ACME)으로 만료 장애를 없앤다.

## 범위 밖 (Non-goals)

- 공동인증서(구 공인인증서) 발급 기관 역할.
- 고객 대상(B2C) 대규모 회원 인증.

## 사용자 / 사용 시나리오

1. 직원이 한 번 로그인하고 MFA를 거치면 연동된 사내 시스템에 바로 접속한다.
2. 위험도가 높은 접속(새 기기, 해외 IP)은 추가 인증을 요구한다.
3. 서버 담당자는 ACME로 내부 인증서를 자동 발급·갱신하고, 만료 예정 목록을 받는다.
4. 연동 담당자는 레거시 시스템 로그인 화면 정보를 넣고 AI가 만든 커넥터를 테스트한다.

## 핵심 기능

- [ ] OIDC·SAML IdP와 SSO
- [ ] MFA(TOTP, 푸시, FIDO2/패스키)와 위험 기반 인증
- [ ] 레거시 연동 커넥터
- [ ] 사설 CA, ACME 자동 발급·갱신, 인증서 인벤토리
- [ ] 인증 감사 로그

## 기술 구상

- 기술 스택: Keycloak 기반 확장 또는 Go 자체 구현, step-ca 참고, HSM 연동, 모바일 인증 앱(Kotlin/Swift)
- 아키텍처: IdP(인증·세션) ↔ MFA 서비스 ↔ 사용자 디렉터리(AD/LDAP) / CA(발급·폐기·OCSP) ↔ ACME 서버 / 커넥터 → 레거시 시스템
- 외부 연동: AD/LDAP, 인사, 접근통제(DB·서버), NAC, SIEM
- AI 자동 개발 적용점:
  - 표준 준수: RFC·사양 → 적합성 테스트 케이스 생성(OIDC 인증 테스트 스위트 보완)
  - 커넥터: 레거시 로그인 흐름 → 커넥터 코드와 E2E 테스트
  - 인벤토리: 네트워크 스캔·설정 파일 → 인증서 위치·만료 목록

## 구현 단계 (MVP → 확장)

1. MVP: 오픈소스 IdP 기반 SSO + TOTP MFA + 사내 시스템 3개 연동.
2. FIDO2·푸시 인증, 레거시 커넥터 자동 생성, 인증서 인벤토리.
3. 사설 CA·ACME, 위험 기반 인증, 다른 접근통제 제품과 통합 정책.

## 열린 질문 / 리스크

- 신규 영역 → 직접 구현할 범위와 오픈소스 확장 범위.
- 인증 서버 장애는 전사 업무 중단 → 고가용성 설계 필수.
- 암호 구현은 검증된 라이브러리만 사용하고 AI가 암호 알고리즘을 직접 구현하지 않는다.
