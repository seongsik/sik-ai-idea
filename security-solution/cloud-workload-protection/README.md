# 클라우드 워크로드 보호 (CWPP)

> 한 줄 요약: 클라우드의 VM·컨테이너·쿠버네티스 워크로드에서 취약 이미지, 잘못된 설정, 런타임 이상 행위를 찾는 보호 솔루션을, 점검 정책과 탐지 룰을 AI로 자동 개발해 만든다.

- 카테고리: security-solution
- 영역: ENDPOINT (단말 안에서 동작)
- 사내 개발 경험: 없음 (신규 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 컨테이너 이미지·쿠버네티스 매니페스트·클라우드 설정이 매일 바뀌어 점검을 사람이 따라가기 어렵다.
- 클라우드 서비스(AWS·Azure·GCP·국내 클라우드)마다 설정 항목이 달라 점검 정책을 따로 만들어야 한다.
- 런타임 공격(컨테이너 탈출, 암호화폐 채굴)은 기존 단말 백신으로 잡기 어렵다.

## 목표

- 이미지 취약점·시크릿·설정 오류를 배포 전에 차단한다.
- 클라우드 보안 가이드·CIS 벤치마크 문서에서 점검 정책(Rego 등)을 AI로 자동 생성한다.
- eBPF 기반 런타임 이벤트로 이상 행위를 탐지한다.

## 범위 밖 (Non-goals)

- 클라우드 비용 관리.
- 클라우드 계정·IAM 거버넌스 전체(CIEM)는 2단계 이후 검토.

## 사용자 / 사용 시나리오

1. DevOps 엔지니어가 CI에 이미지·매니페스트 점검을 넣는다. 고위험 항목이 있으면 배포가 막힌다.
2. 클러스터에 배포된 에이전트(DaemonSet)가 런타임 이벤트를 수집한다.
3. 컨테이너에서 셸 실행, 민감 경로 쓰기 등이 일어나면 경보와 함께 관련 파드·이미지 정보를 보여 준다.
4. 보안 담당자는 국내 클라우드 보안 인증 기준에 맞춘 점검 보고서를 받는다.

## 핵심 기능

- [ ] 이미지 취약점·시크릿 스캔
- [ ] IaC·매니페스트·클라우드 설정 점검(정책 코드)
- [ ] 배포 차단(어드미션 컨트롤러)
- [ ] eBPF 런타임 탐지
- [ ] 기준별 점검 보고서(CIS, 국내 클라우드 보안 기준)

## 기술 구상

- 기술 스택: Go(에이전트·서버), eBPF(Falco/Tetragon 참고), OPA/Rego, Trivy 참고
- 아키텍처: CI 스캐너 / 어드미션 컨트롤러 / 런타임 에이전트 → 중앙 서버 → 콘솔·SIEM
- 외부 연동: 컨테이너 레지스트리, 클라우드 API, 쿠버네티스 API, SIEM
- AI 자동 개발 적용점:
  - 정책 생성: 벤치마크 문서 항목 → Rego 정책 + 위반/준수 테스트 픽스처
  - 런타임 룰: 공격 기법 설명 → Falco 형식 룰 + 재현 시나리오
  - 클라우드 확장: 새 클라우드 API 문서 → 설정 수집기 코드

## 구현 단계 (MVP → 확장)

1. MVP: 이미지·매니페스트 스캐너(CLI·CI) + 점검 보고서.
2. 어드미션 컨트롤러, 클라우드 설정 점검, 정책 자동 생성 도구.
3. eBPF 런타임 탐지, 국내 클라우드 지원.

## 열린 질문 / 리스크

- 신규 영역 → 오픈소스(Trivy, Falco) 활용 범위와 차별점.
- 클라우드 API 권한(읽기 전용) 설계와 고객 신뢰.
- eBPF 커널 버전 호환성.
