# AI·LLM 보안

> 한 줄 요약: 사내 직원의 생성형 AI 사용과 사내 LLM 서비스를 보호하는 AI 보안 게이트웨이를, 프롬프트 인젝션·민감정보 유출 탐지 룰과 레드팀 테스트를 AI로 자동 개발해 만든다.

- 카테고리: security-solution
- 영역: ACCESS (사람과 권한을 통제)
- 사내 개발 경험: 없음 (신규 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 직원이 외부 생성형 AI에 고객 정보·소스 코드를 붙여 넣는 유출 위험이 있다.
- 사내 LLM 서비스(RAG 챗봇, 에이전트)는 프롬프트 인젝션, 권한 밖 문서 노출, 도구 오남용 위험이 있다.
- 공격 기법이 빠르게 바뀌어 고정 룰로는 대응하기 어렵다.

## 목표

- 외부 AI 서비스 사용 시 민감정보(개인정보, 기밀 키워드, 소스 코드)를 탐지해 마스킹·차단·경고한다.
- 사내 LLM 앞단에서 입력·출력을 검사해 인젝션과 민감정보 노출을 막는다.
- 공격 프롬프트를 AI로 자동 생성하는 레드팀 테스트로 방어 룰과 사내 LLM 서비스를 계속 검증한다.

## 범위 밖 (Non-goals)

- LLM 모델 자체 학습·개발.
- AI 생성 콘텐츠 저작권 판정.

## 사용자 / 사용 시나리오

1. 직원이 외부 AI 서비스에 질문하면 게이트웨이(프록시·브라우저 확장)가 입력을 검사한다. 개인정보는 마스킹되고, 기밀 문서는 차단·경고된다.
2. 사내 RAG 챗봇의 질의·응답이 게이트웨이를 거치며, 사용자 권한 밖 문서 인용과 인젝션 시도가 차단된다.
3. 보안 담당자는 사용 현황(서비스별, 부서별, 차단 건수)을 대시보드로 본다.
4. 개발팀은 매일 자동 레드팀 결과로 방어 룰 약점을 보완한다.

## 핵심 기능

- [ ] 외부 AI 서비스 사용 통제(허용 목록, 민감정보 마스킹·차단)
- [ ] LLM 입력·출력 검사(프롬프트 인젝션, 탈옥, 민감정보, 유해 출력)
- [ ] 에이전트 도구 호출 정책(허용 도구, 승인 필요 작업)
- [ ] 자동 레드팀(공격 프롬프트 생성·평가)
- [ ] 사용 감사 로그와 대시보드

## 기술 구상

- 기술 스택: Go/Python(게이트웨이), 브라우저 확장, 분류 모델(인젝션·민감정보, 온프레미스), 정책 엔진
- 아키텍처: 사용자 → 게이트웨이(입력 검사 → 정책 판정 → 마스킹) → LLM → 게이트웨이(출력 검사) → 사용자 / 로그 → 대시보드·SIEM
- 외부 연동: 개인정보 검색 엔진(패턴), DRM(문서 등급), 인증(SSO 사용자 식별), SIEM
- AI 자동 개발 적용점:
  - 레드팀: 공격 기법 목록 → 변형 공격 프롬프트 생성과 성공 여부 자동 평가
  - 탐지: 레드팀 성공 사례 → 탐지 룰·분류 학습 데이터 보강
  - 정책: 사내 AI 사용 지침 문서 → 정책 설정 초안

## 구현 단계 (MVP → 확장)

1. MVP: 외부 AI 서비스 프록시 + 개인정보 마스킹 + 사용 로그.
2. 사내 LLM 입력·출력 검사, 자동 레드팀 파이프라인.
3. 에이전트 도구 호출 정책, MCP 등 도구 연동 프로토콜 검사, 문서 권한 연계 RAG 보호.

## 열린 질문 / 리스크

- 신규 영역이며 기술 변화가 빨라 표준·규제(AI 기본법 등) 추적 필요.
- 검사 자체를 외부 LLM으로 하면 또 다른 유출 경로 → 검사 모델은 온프레미스.
- 응답 지연이 커지면 사용자가 우회 → 지연 목표 설정.
