# OT·IoT 보안

> 한 줄 요약: 공장·빌딩 제어망과 IoT 기기의 자산을 수동(passive) 방식으로 식별하고 이상 통신을 탐지하는 보안 솔루션을, 산업용 프로토콜 파서와 탐지 모델을 AI로 자동 개발해 만든다.

- 카테고리: security-solution
- 영역: NETWORK (패킷이 지나가는 길목)
- 사내 개발 경험: 없음 (신규 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 제어망(PLC, HMI, SCADA)은 장비를 멈출 수 없어 능동 스캔·에이전트 설치가 어렵다.
- Modbus, DNP3, S7, EtherNet/IP, BACnet 등 프로토콜이 많고 벤더 확장이 제각각이다.
- 제어망 통신은 패턴이 일정하므로 "평소와 다른 명령"을 잡는 것이 효과적인데, 이를 위한 기준선 작성이 수작업이다.

## 목표

- 미러링 트래픽만으로 OT·IoT 자산(벤더, 모델, 펌웨어)을 자동 식별한다.
- 산업용 프로토콜 파서를 명세에서 AI로 생성하고 퍼징으로 검증한다.
- 통신 기준선을 자동 학습해 비인가 쓰기 명령, 펌웨어 변경, 신규 통신을 탐지한다.

## 범위 밖 (Non-goals)

- 제어 명령의 인라인 차단 (안전 문제로 1단계는 탐지만).
- 기기 펌웨어 취약점 분석(바이너리 분석).

## 사용자 / 사용 시나리오

1. 공장 보안 담당자가 제어망 스위치 미러 포트에 센서를 연결한다.
2. 센서가 트래픽으로 자산 목록과 통신 지도를 만든다.
3. 2~4주 학습 후 기준선에서 벗어난 통신(예: 업무 시간 외 PLC 쓰기)을 경보로 보낸다.
4. 경보에는 어떤 장비에 어떤 명령이 갔는지 사람이 읽을 수 있는 설명이 붙는다.

## 핵심 기능

- [ ] 수동 방식 자산 식별과 통신 지도
- [ ] 산업용 프로토콜 심층 분석(명령·레지스터 수준)
- [ ] 통신 기준선 학습과 이상 탐지
- [ ] 알려진 OT 취약점(ICS 권고) 매칭
- [ ] 경보 설명 자동 생성

## 기술 구상

- 기술 스택: Rust/C(센서), Zeek 또는 자체 파서, Python(분석), 시계열 DB, 웹 콘솔
- 아키텍처: 센서(미러 포트) → 프로토콜 파서 → 자산·통신 이벤트 → 중앙 분석(기준선·탐지) → 콘솔·SIEM
- 외부 연동: CISA ICS 권고, 자산관리, SIEM
- AI 자동 개발 적용점:
  - 파서: 프로토콜 명세·Wireshark 디섹터 참고 → 파서 + 퍼징 테스트
  - 자산 식별: 패킷 특징 → 벤더·모델 식별 규칙 제안
  - 경보 설명: 레지스터·명령 코드 → 운영자용 문장

## 구현 단계 (MVP → 확장)

1. MVP: Modbus/TCP·BACnet 대상 자산 식별 + 통신 지도 + 신규 통신 탐지.
2. 프로토콜 확대(S7, DNP3, EtherNet/IP), 명령 수준 기준선.
3. 원격 사이트 다중 센서, IoT(카메라·출입통제) 확대, 제한적 차단 연계.

## 열린 질문 / 리스크

- 신규 영역 → 시험용 OT 랩(PLC 실장비 또는 시뮬레이터) 확보 필요.
- 프로토콜 명세가 비공개인 벤더 확장.
- 센서가 제어망에 영향을 주지 않음을 보장하는 설계(송신 금지).
