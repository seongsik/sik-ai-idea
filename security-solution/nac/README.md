# 네트워크 접근 통제 (NAC)

> 한 줄 요약: 네트워크에 접속하는 단말을 식별·검사해 허용·격리·차단하는 NAC를, 단말 식별 규칙·장비 연동 어댑터·정책 검증을 AI로 자동 개발한다.

- 카테고리: security-solution
- 영역: NETWORK (패킷이 지나가는 길목)
- 사내 개발 경험: 있음 (현업에서 직접 개발한 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 스위치·무선 컨트롤러 벤더와 모델이 다양해 연동 모듈(SNMP, 802.1X/RADIUS, API)을 장비마다 따로 만들어야 한다.
- IoT·프린터·개인 단말이 늘면서 단말 종류 식별(핑거프린팅) 규칙을 사람이 계속 추가해야 한다.
- 접근 정책이 복잡해져 "이 정책이 어떤 단말을 막는지" 배포 전에 알기 어렵다.

## 목표

- 장비 매뉴얼·MIB·API 문서를 입력하면 연동 어댑터 코드와 테스트를 자동 생성한다.
- DHCP·MAC OUI·HTTP UA·트래픽 특성으로 단말 종류를 자동 분류하고, 미분류 단말의 규칙을 AI가 제안한다.
- 정책 변경 전 시뮬레이션으로 영향 받는 단말 목록을 보여 준다.

## 범위 밖 (Non-goals)

- 단말 내부 보안 점검 에이전트의 전체 기능(백신 수준 검사). 무결성 점검 항목(OS 패치, 백신 설치 여부) 확인만 한다.
- 무선 AP 자체 개발.

## 사용자 / 사용 시나리오

1. 단말이 네트워크에 연결되면 NAC가 MAC·IP·DHCP 정보를 수집해 단말을 식별한다.
2. 등록된 사용자·단말이면 정책에 따라 VLAN을 배정하고, 미등록이면 격리 VLAN과 등록 포털로 보낸다.
3. 관리자가 정책을 바꾸면 시뮬레이터가 "현재 접속 단말 중 차단될 대상"을 미리 보여 준다.
4. 새 스위치 모델을 도입하면 개발자가 매뉴얼을 넣고 AI가 연동 어댑터를 만든다.

## 핵심 기능

- [ ] 단말 탐지·식별(에이전트리스) 및 자동 분류
- [ ] 802.1X/RADIUS, SNMP, 벤더 API 기반 차단·격리
- [ ] 사용자·단말 등록 포털과 승인 흐름
- [ ] 정책 시뮬레이션(영향 단말 미리보기)
- [ ] 장비 연동 어댑터 자동 생성 도구

## 기술 구상

- 기술 스택: Go 또는 Java(서버), FreeRADIUS 연동, PostgreSQL, 웹 콘솔(React)
- 아키텍처: 센서(미러 포트·DHCP 수집) → 단말 식별 엔진 → 정책 엔진 → 집행 어댑터(스위치·무선·방화벽) → 콘솔
- 외부 연동: 인사·AD/LDAP, 자산관리, 백신·EDR 상태, SIEM
- AI 자동 개발 적용점:
  - 어댑터: 벤더 문서 → 어댑터 인터페이스 구현 + 장비 응답 모의(mock) 테스트
  - 핑거프린팅: 미분류 단말 특성 묶음 → 분류 규칙 제안
  - 정책: 자연어 정책 → 정책 DSL 변환과 충돌 검사

## 구현 단계 (MVP → 확장)

1. MVP: 에이전트리스 단말 탐지·식별 + SNMP 포트 차단 + 등록 포털.
2. 802.1X 연동, 정책 시뮬레이션, 어댑터 자동 생성 도구.
3. EDR·MDM 상태 연계 동적 정책, 제로 트러스트 접근 정책과 통합.

## 열린 질문 / 리스크

- 실제 장비 없이 AI가 만든 어댑터를 검증할 방법 → 장비 응답 녹화 기반 테스트, 실장비 랩 필요.
- 오분류로 업무 단말이 차단되는 위험 → 신규 규칙은 "모니터 모드"로 먼저 운영.
- 기존 사내 NAC 제품과 코드 재사용 범위.
