# 웹방화벽 (WAF)

> 한 줄 요약: 웹 애플리케이션 앞에서 HTTP 요청을 검사해 SQL 인젝션·XSS 등 공격을 막는 WAF를, 신규 영역이지만 AI 자동 개발로 룰셋·우회 테스트·애플리케이션별 허용 정책 학습까지 갖춰 개발한다.

- 카테고리: security-solution
- 영역: NETWORK (패킷이 지나가는 길목)
- 사내 개발 경험: 없음 (신규 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 범용 룰셋만으로는 오탐이 많아 도입 후 "탐지만" 모드로 방치되는 경우가 많다.
- 애플리케이션마다 정상 요청 형태가 달라 예외 정책을 사람이 하나씩 만든다.
- 인코딩·대소문자·주석 삽입 등 우회 기법이 계속 나온다.

## 목표

- OWASP CRS 수준의 기본 룰셋을 갖추고, AI로 우회 변형 공격을 생성해 룰을 지속 검증한다.
- 학습 기간의 정상 트래픽으로 애플리케이션별 허용 정책(파라미터 형식, 길이)을 자동 제안한다.
- 오탐 신고 시 원인 룰과 예외 정책 초안을 자동으로 만든다.

## 범위 밖 (Non-goals)

- DDoS 대응(대용량 트래픽 흡수)과 CDN 기능.
- 봇 관리 전용 기능(1단계에서는 제외).

## 사용자 / 사용 시나리오

1. 보안 담당자가 보호할 웹 서비스를 등록하고 학습 모드로 2주간 운영한다.
2. AI가 정상 요청을 분석해 URL·파라미터별 허용 정책을 제안하고, 담당자가 승인한다.
3. 차단 모드로 바꾼 뒤 오탐 신고가 들어오면 원인 룰과 예외 초안이 자동 작성된다.
4. 개발팀은 매일 우회 공격 자동 생성 테스트 결과로 룰 약점을 보완한다.

## 핵심 기능

- [ ] 리버스 프록시 방식 HTTP/HTTPS 검사·차단
- [ ] 기본 룰셋(OWASP Top 10) + 사용자 정의 룰
- [ ] 학습 기반 애플리케이션별 허용 정책 제안
- [ ] 오탐 분석과 예외 정책 초안 생성
- [ ] 우회 변형 공격 자동 생성 테스트(CI)

## 기술 구상

- 기술 스택: NGINX/Envoy + ModSecurity(Coraza) 또는 자체 엔진(Go/Rust), 관리 콘솔(React), PostgreSQL
- 아키텍처: TLS 종료 → 요청 정규화(디코딩) → 룰 엔진 → 허용 정책 검사 → 차단/통과 → 로그·SIEM
- 외부 연동: 인증서 관리, SIEM, 취약점 진단 결과(가상 패치)
- AI 자동 개발 적용점:
  - 우회 테스트: 공격 페이로드 → 인코딩·분할·문법 변형 자동 생성
  - 허용 정책: 정상 로그 → 파라미터 스키마 추론
  - 가상 패치: 취약점 진단 보고서 → 해당 URL 전용 차단 룰 초안

## 구현 단계 (MVP → 확장)

1. MVP: Coraza + OWASP CRS 기반 프록시, 탐지 모드, 로그 콘솔, 우회 테스트 파이프라인.
2. 학습 기반 허용 정책, 오탐 분석 보조, 차단 모드.
3. API 보호(OpenAPI 스키마 검증), 진단 결과 연동 가상 패치, 클라우드형 제공.

## 열린 질문 / 리스크

- 신규 영역이라 시장 진입 전략(기존 제품 대비 차별점).
- TLS 복호화에 필요한 인증서·키 관리와 성능.
- 오픈소스 엔진 라이선스(Apache 2.0 등) 검토.
