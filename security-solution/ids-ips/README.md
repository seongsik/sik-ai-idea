# 침입탐지·방지 시스템 (IDS/IPS)

> 한 줄 요약: 네트워크 트래픽을 실시간 검사해 공격을 탐지·차단하는 IDS/IPS를, 탐지 룰 작성·프로토콜 파서·회귀 테스트를 AI로 자동화해 빠르게 개발·유지보수한다.

- 카테고리: security-solution
- 영역: NETWORK (패킷이 지나가는 길목)
- 사내 개발 경험: 있음 (현업에서 직접 개발한 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 신규 취약점(CVE)이 나올 때마다 탐지 시그니처를 사람이 분석해 작성하므로 대응이 늦고, 룰 품질이 작성자에 따라 다르다.
- 프로토콜 파서(HTTP, DNS, SMB, 산업용 프로토콜 등)를 추가할 때 RFC 해석과 예외 처리에 개발 시간이 많이 든다.
- 룰이 수만 개로 늘면서 오탐·성능 저하를 사람이 추적하기 어렵다.

## 목표

- CVE·공격 PoC를 입력하면 탐지 룰 초안과 검증용 공격/정상 트래픽(pcap)을 자동 생성한다.
- 새 프로토콜 파서를 명세(RFC)에서 코드와 퍼징 테스트까지 자동 생성한다.
- 룰 변경마다 탐지율·오탐률·처리량 회귀 테스트를 자동으로 돌린다.

## 범위 밖 (Non-goals)

- 패킷 처리 엔진(DPI 코어) 자체를 AI가 처음부터 설계하는 것. 코어는 기존 엔진 또는 오픈소스(Suricata 등)를 기반으로 한다.
- AI가 운영 장비에 룰을 직접 배포하는 것 (배포는 사람 승인 후).

## 사용자 / 사용 시나리오

1. 위협 분석가가 신규 CVE 번호와 공개 PoC를 등록한다.
2. AI가 취약점 원리를 요약하고 탐지 룰 초안(Suricata/Snort 호환 또는 자사 문법)과 공격·정상 pcap을 만든다.
3. CI가 룰을 시험 엔진에 올려 탐지 여부, 기존 정상 트래픽 코퍼스 대비 오탐, 처리량 영향을 측정한다.
4. 분석가가 결과를 검토·승인하면 룰 패키지로 배포된다.

## 핵심 기능

- [ ] CVE·PoC 기반 탐지 룰 초안 자동 생성
- [ ] 룰 검증용 공격·정상 트래픽 자동 생성 (pcap)
- [ ] 프로토콜 파서 코드·퍼징 테스트 자동 생성
- [ ] 룰 회귀 테스트(탐지율, 오탐률, 처리량) CI
- [ ] 중복·충돌·저효율 룰 정리 제안

## 기술 구상

- 기술 스택: C/C++ 또는 Rust(패킷 처리), Python(룰 도구·테스트 하네스), Suricata 호환 룰 문법
- 아키텍처: 패킷 수집(AF_PACKET/DPDK) → 세션 재조립 → 프로토콜 파서 → 룰 매칭 → 탐지/차단 이벤트 → 관리 콘솔·SIEM
- 외부 연동: NVD·KISA 취약점 공지, 위협 인텔 피드, SIEM(syslog/CEF)
- AI 자동 개발 적용점:
  - 룰 생성: CVE 설명·PoC 코드 → 룰 초안 + 근거 설명
  - 테스트 데이터: 공격 변형(인코딩·분할) pcap 생성으로 우회 내성 확인
  - 파서: 명세 → 파서 코드 + 퍼저 하네스(libFuzzer/AFL) 생성

## 구현 단계 (MVP → 확장)

1. MVP: 오픈소스 엔진 위에서 웹 공격(HTTP) CVE 대상 룰 자동 생성 + 회귀 테스트 파이프라인.
2. 자사 정상 트래픽 코퍼스 구축과 오탐 자동 측정, 룰 정리 제안.
3. 신규 프로토콜 파서 자동 생성, IPS 인라인 차단 모드 성능 튜닝.

## 열린 질문 / 리스크

- AI가 만든 룰의 우회 가능성 → 변형 공격 트래픽으로 반드시 검증한다.
- 고객사 트래픽을 학습·검증에 쓸 수 있는 범위 (개인정보 포함 가능).
- 인라인 IPS의 지연·장애 시 우회(fail-open) 정책.
- CC인증 등 인증 대상 제품이면 AI 생성 코드의 형상관리·추적성 요구.
