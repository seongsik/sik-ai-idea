# DB·서버 접근통제

> 한 줄 요약: DB와 서버에 접속하는 사용자·명령을 통제하고 기록하는 접근통제 솔루션을, DBMS·프로토콜별 파서와 위험 명령 정책을 AI로 자동 개발해 지원 범위를 넓힌다.

- 카테고리: security-solution
- 영역: ACCESS (사람과 권한을 통제)
- 사내 개발 경험: 있음 (현업에서 직접 개발한 영역)
- 상태: 아이디어
- 작성일: 2026-11-12
- 구현 리포지터리: -

## 배경 / 문제

- 지원해야 할 DBMS(Oracle, MSSQL, MySQL, PostgreSQL, Tibero, 클라우드 DB)와 프로토콜(SSH, RDP, Telnet) 버전이 계속 늘어난다.
- 와이어 프로토콜 파서를 버전마다 손봐야 하고, 회귀 테스트가 부족해 업그레이드 후 장애가 난다.
- 대량 조회·권한 변경 같은 위험 행위 판단 기준을 고객마다 따로 정책으로 만든다.

## 목표

- DBMS 와이어 프로토콜 파서를 AI 지원으로 생성하고, 실제 DB 컨테이너 대상 자동 회귀 테스트를 만든다.
- 위험 SQL·명령을 분류하는 정책 템플릿을 제공하고, 자연어로 정책을 정의하게 한다.
- 접속 이력·쿼리 로그로 이상 접근(평소와 다른 시간·대량 조회)을 탐지한다.

## 범위 밖 (Non-goals)

- DB 성능 모니터링(APM).
- 계정 생명주기 관리(IAM) 전체.

## 사용자 / 사용 시나리오

1. DBA·개발자가 게이트웨이를 거쳐 DB·서버에 접속한다. 승인된 계정·시간·IP만 허용된다.
2. 개인정보 테이블 대량 조회나 DROP 같은 위험 명령은 차단되거나 결재 후 실행된다.
3. 모든 쿼리·명령과 결과 건수가 기록되고, 감사 시 보고서로 제출된다.
4. 개발팀은 새 DBMS 버전이 나오면 컨테이너 테스트에서 실패한 파서 항목과 AI 수정안을 확인한다.

## 핵심 기능

- [ ] 게이트웨이(프록시) 방식 DB 접근통제
- [ ] SSH·RDP 서버 접근통제와 세션 기록
- [ ] 위험 명령 정책(차단·결재·경고)과 개인정보 컬럼 마스킹
- [ ] 접속·쿼리 감사 로그와 보고서
- [ ] 이상 접근 탐지
- [ ] DBMS 버전 매트릭스 자동 회귀 테스트

## 기술 구상

- 기술 스택: C/C++ 또는 Go(프록시), SQL 파서(각 DBMS 방언), PostgreSQL(정책·로그), 웹 콘솔
- 아키텍처: 클라이언트 → 접근통제 게이트웨이(인증 → 프로토콜 파싱 → SQL 분석 → 정책 판정) → DB·서버 / 로그 → 감사·탐지
- 외부 연동: 인사·AD, 결재 시스템, MFA, SIEM, 개인정보 검색(민감 컬럼 식별)
- AI 자동 개발 적용점:
  - 파서: 프로토콜 문서·패킷 캡처 → 파서 코드 + 버전별 테스트
  - 테스트: DBMS 컨테이너 × 클라이언트 도구 조합 회귀 시나리오 생성
  - 정책: 자연어 → 정책 규칙, 위험 SQL 분류 근거 설명

## 구현 단계 (MVP → 확장)

1. MVP: 기존 제품에 DBMS 버전 매트릭스 회귀 테스트와 파서 수정 보조 도입.
2. 위험 SQL 정책 템플릿과 자연어 정책, 이상 접근 탐지.
3. 클라우드 DB·쿠버네티스 접근통제, 임시 권한(JIT) 발급.

## 열린 질문 / 리스크

- 상용 DBMS 프로토콜 문서 비공개 부분과 라이선스.
- 게이트웨이 장애 시 업무 중단 → 이중화와 우회 정책.
- 쿼리 결과 기록 시 개인정보 저장 문제.
