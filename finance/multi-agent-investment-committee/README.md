# 멀티에이전트 투자심의 포트폴리오 자문

> 한 줄 요약: 뉴스, SNS, 증시를 24시간 감시해 종목을 발굴하고, 성향이 다른 AI 운용역들이 투자심의를 거쳐 각자의 포트폴리오로 경쟁하며, 그 결과를 바탕으로 개인 자산관리 조언과 리스크 경보를 주는 멀티에이전트 시스템

- 카테고리: finance
- 상태: 아이디어
- 작성일: 2026-11-06
- 구현 리포지터리: 없음

## 배경 / 문제

- 본인 자산을 직접 관리하지만, 본업이 있어 장중과 해외장(야간)의 뉴스, 공시, 시세 변화를 실시간으로 따라갈 수 없다.
- 종목 발굴은 우연히 본 뉴스나 커뮤니티 글에 기대게 되고, 가치 분석은 시간이 없어 생략하기 쉽다.
- 매수 근거와 매도 기준을 기록하지 않아 같은 실수를 반복하고, 보유 종목의 악재를 늦게 안다.
- AI 하나에게 물으면 한 가지 관점으로 그럴듯한 답만 돌아온다. 서로 다른 관점이 반박하고, 실적으로 검증받는 구조가 필요하다.

## 목표

- 보유 종목과 관심 종목에 영향을 주는 사건(공시, 뉴스, SNS 급증, 가격·거래량 이상)을 발생 후 수 분 안에 알린다.
- 매일 새로운 종목 후보를 찾고, 각 후보에 근거 자료가 달린 가치 분석 보고서를 만든다.
- 투자 판단은 투자심의(제안 → 반론 → 리스크 검토 → 표결)를 거친 것만 조언으로 낸다.
- 성향이 다른 AI 운용역들이 각자 가상 포트폴리오를 운용하고, 성과를 같은 기준으로 비교해 어느 관점을 얼마나 믿을지 데이터로 정한다.
- 실제 포트폴리오의 집중도, 손실 한도, 변동성을 상시 점검하고 한도를 넘으면 경보를 보낸다.

## 범위 밖 (Non-goals)

- **자동 주문 실행.** 시스템은 조언과 경보만 낸다. 실제 매매는 사용자가 직접 한다.
- 다른 사람에게 자문을 제공하거나 판매하는 것. 그렇게 하면 투자자문업 등록 대상이 된다. 본인 전용으로만 쓴다.
- 초단타(초·분 단위) 매매 신호. 판단 주기는 수 분 이상이다.
- 파생상품, 레버리지, 공매도 전략. 1차 범위는 현물 주식과 ETF다.

## 사용자 / 사용 시나리오

사용자는 본인 한 명이다.

1. **아침 브리핑 (07:30):** 밤사이 미국장 결과, 보유 종목 관련 뉴스와 공시, 오늘 일정(실적 발표, 경제지표)을 메신저로 받는다.
2. **장중 경보:** 보유 종목에 악재 공시가 뜨면, 공시 요약과 영향 판단, 리스크 담당의 권고(유지·축소·관찰)를 바로 받는다.
3. **종목 발굴:** 발굴 담당이 SNS 언급 급증과 실적 개선 공시를 함께 잡아낸 종목을 후보로 올린다. 가치 분석 보고서가 붙고, 다음 투자심의 안건이 된다.
4. **투자심의 (매일 장 마감 후, 또는 긴급 소집):** 운용역들이 후보와 보유 종목에 대해 매수·매도를 제안한다. 반론 담당이 반박하고, 리스크 담당이 한도를 검토한 뒤 표결한다. 사용자는 회의록과 결론을 받는다.
5. **주간 성과 리뷰:** 운용역별 가상 포트폴리오의 수익률, 최대 낙폭, 적중률 순위와 실제 포트폴리오와의 차이를 받는다.
6. **질문:** "지금 반도체 비중 줄여야 해?"라고 물으면 현재 데이터와 운용역들의 의견을 모아 답한다.

## 핵심 기능

### 감시 (24시간)

- [ ] 뉴스 수집: 국내외 경제 뉴스 RSS와 뉴스 API. 종목과 테마에 연결하고 중복 기사를 묶는다.
- [ ] 공시 수집: 국내 DART, 미국 SEC EDGAR. 공시 유형별 중요도를 매긴다(유상증자, 최대주주 변경, 실적, 소송 등).
- [ ] SNS·커뮤니티 수집: 종목 언급량, 감성, 급증을 측정한다. 출처별 신뢰도를 따로 둔다.
- [ ] 시세 감시: 가격, 거래량, 수급(외국인·기관) 이상을 탐지한다. 국내장, 미국장, 시간외 거래를 포함한다.
- [ ] 일정: 실적 발표, 배당, 경제지표, FOMC 같은 이벤트 달력.

### 분석

- [ ] 종목 발굴: 여러 신호(뉴스, 공시, SNS, 수급, 가격)가 겹치는 종목을 점수화해 후보 목록을 만든다.
- [ ] 가치 분석 보고서: 사업 요약, 재무(성장성, 수익성, 부채), 밸류에이션(PER, PBR, EV/EBITDA, 동종 비교), 촉매와 리스크, 근거 링크.
- [ ] 이벤트 영향 분석: 공시나 뉴스 한 건이 보유 종목에 주는 영향을 판단한다.

### 투자심의와 경쟁

- [ ] 운용역 에이전트: 성향이 다른 여러 운용역(예: 가치, 성장, 모멘텀, 배당·방어, 역발상)이 같은 정보를 보고 각자 판단한다.
- [ ] 가상 포트폴리오: 운용역마다 같은 초기 자금으로 가상 운용한다. 거래 비용과 세금을 반영한다.
- [ ] 투자심의 절차: 안건 상정 → 운용역별 의견 → 반론 담당 반박 → 리스크 담당 한도 검토 → 표결 → 회의록.
- [ ] 성과 평가: 운용역별 수익률, 최대 낙폭, 샤프 비율, 적중률. 성과에 따라 심의 표결 가중치를 조정한다.

### 리스크 관리

- [ ] 실제 포트폴리오 입력: 증권사 계좌 조회 API 또는 수동 입력.
- [ ] 한도 점검: 종목·섹터·국가 집중도, 손절선, 포트폴리오 최대 낙폭, 현금 비중.
- [ ] 상관관계와 변동성 점검, 시나리오 손실 추정(예: 지수 -10%일 때).
- [ ] 경보: 한도 초과, 손절선 접근, 보유 종목 악재.

### 전달

- [ ] 메신저 알림(텔레그램 등): 긴급 경보, 아침 브리핑, 심의 결과.
- [ ] 대시보드: 포트폴리오, 운용역 순위, 심의 기록, 종목 보고서.
- [ ] 투자 일지: 사용자의 실제 매매와 그 시점의 심의 의견을 함께 기록한다. 나중에 판단을 복기할 수 있다.

## 기술 구상

- 기술 스택: Python. 에이전트 오케스트레이션은 LLM API(Claude 등)와 도구 호출. 데이터 저장은 PostgreSQL(시계열은 TimescaleDB 등). 작업 예약은 스케줄러와 이벤트 큐.
- 아키텍처:
  1. **수집 계층 (LLM 없음):** 뉴스, 공시, SNS, 시세 수집기가 정해진 주기나 실시간 스트림으로 데이터를 모아 저장한다.
  2. **신호 계층 (규칙과 통계):** 급증, 이상치, 중요 공시 유형을 규칙으로 걸러 "사건"을 만든다. 여기서 걸러진 사건만 LLM으로 넘겨 비용을 줄인다.
  3. **에이전트 계층:** 발굴 담당, 분석 담당, 운용역들, 반론 담당, 리스크 담당, 심의 의장.
  4. **포트폴리오 계층 (LLM 없음):** 가상·실제 포트폴리오 회계, 성과 계산, 한도 점검. 숫자 계산은 전부 코드로 한다.
  5. **전달 계층:** 메신저 봇, 대시보드.
- 원칙:
  - 수치(가격, 재무, 수익률)는 데이터에서 코드로 계산한다. LLM은 해석과 토론만 한다.
  - LLM이 낸 모든 주장에는 근거 데이터나 출처 링크를 붙인다. 근거가 없는 주장은 심의에서 제외한다.
  - 작업 성격에 따라 모델을 나눈다. 대량 요약과 분류는 경량 모델, 가치 분석과 심의는 상위 모델을 쓴다.
- 외부 연동 (후보):
  - 국내 시세와 계좌: 증권사 OpenAPI (예: 한국투자증권 KIS Developers)
  - 국내 공시: DART OpenAPI
  - 미국 공시: SEC EDGAR
  - 미국 시세와 재무: 유료 데이터 API(무료 플랜은 지연 시세)
  - 뉴스: 언론사 RSS, 뉴스 검색 API
  - SNS: X(유료 API), Reddit, 텔레그램 공개 채널. 커뮤니티 수집은 각 서비스 약관을 확인한다.
  - 경제지표: 한국은행 ECOS, FRED

## 구현 단계 (MVP → 확장)

1. **MVP: 감시와 경보.** 보유 종목 수동 입력, DART 공시와 뉴스 RSS 수집, 중요 사건 요약 알림, 아침 브리핑.
2. **가치 분석.** 재무 데이터 연동, 종목 보고서 생성, 관심 종목 관리.
3. **투자심의.** 운용역 3명(가치, 성장, 모멘텀)과 반론·리스크 담당으로 일일 심의, 회의록 생성.
4. **경쟁과 평가.** 운용역별 가상 포트폴리오, 성과 순위, 표결 가중치 조정. 이 단계에서 최소 3개월 가상 운용으로 검증한다.
5. **리스크 관리 강화.** 계좌 API 연동, 한도 점검, 시나리오 분석, 투자 일지.
6. **확장.** SNS 수집, 미국장 실시간 감시, 운용역 추가, 대시보드.

## 열린 질문 / 리스크

- 대상 시장: 국내만, 미국만, 둘 다? 미국을 넣으면 야간 감시와 데이터 비용이 커진다.
- 운용역 구성: 몇 명, 어떤 성향으로 할지. 운용역을 추가하거나 퇴출하는 규칙(예: 6개월 성과 하위는 교체).
- 심의 주기: 매일 1회 정기 심의와, 긴급 소집 조건.
- 실제 계좌 연동 범위: 조회만 할지, 수동 입력으로 갈지. 조회 API 키도 유출되지 않게 보관해야 한다.
- 비용: 24시간 운영의 LLM 사용료, 데이터 API 요금, 서버비. 월 예산 상한을 정하고 초과하면 경량 모델로 내린다.
- **LLM 고유 위험:**
  - 환각: 존재하지 않는 공시나 숫자를 만들 수 있다. 출처를 반드시 붙이고, 수치는 코드로 검증한다.
  - 백테스트 오염: LLM은 학습 시점까지의 실제 주가 흐름을 알고 있어서, 과거 데이터로 검증하면 성과가 부풀려진다. 성능 검증은 **앞으로의 가상 운용**으로만 한다.
  - 같은 모델을 쓰는 운용역들은 의견이 비슷해질 수 있다. 성향별 프롬프트, 입력 데이터, 모델을 다르게 해 다양성을 확보한다.
- SNS 데이터의 조작(펌프앤덤프, 리딩방): 급증 신호만으로 매수 의견을 내지 않게 한다.
- 규제: 본인 전용이면 문제없지만, 결과를 남에게 공유하거나 유료로 제공하면 투자자문업 및 유사투자자문업 규제를 받는다.
- 최종 판단과 책임은 사용자에게 있다. 시스템 의견은 참고 자료다.
