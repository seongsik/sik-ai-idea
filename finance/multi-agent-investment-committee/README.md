# 멀티에이전트 투자심의 포트폴리오 자문

> 한 줄 요약: 국내·미국 증시와 뉴스, SNS를 24시간 감시해 종목을 발굴하고, 분야가 다른 비판적 전문가 운용역 5명이 투자심의를 거쳐 각자의 포트폴리오로 경쟁하며, 그 결과를 바탕으로 개인 자산관리 조언과 리스크 경보를 주는 멀티에이전트 시스템

- 카테고리: finance
- 상태: 구체화 중
- 작성일: 2026-11-06
- 최종 수정: 2026-11-06 (대상 시장, 운용역 구성, 계좌 연동, 비용 결정 방식 반영)
- 구현 리포지터리: 없음

## 배경 / 문제

- 본인 자산을 직접 관리하지만, 본업이 있어 장중과 해외장(야간)의 뉴스, 공시, 시세 변화를 실시간으로 따라갈 수 없다.
- 종목 발굴은 우연히 본 뉴스나 커뮤니티 글에 기대게 되고, 가치 분석은 시간이 없어 생략하기 쉽다.
- 매수 근거와 매도 기준을 기록하지 않아 같은 실수를 반복하고, 보유 종목의 악재를 늦게 안다.
- AI 하나에게 물으면 한 가지 관점으로 그럴듯한 답만 돌아온다. 서로 다른 관점이 반박하고, 실적으로 검증받는 구조가 필요하다.

## 목표

- 보유 종목과 관심 종목에 영향을 주는 사건(공시, 뉴스, SNS 급증, 가격·거래량 이상)을 발생 후 수 분 안에 알린다.
- 매일 새로운 종목 후보를 찾고, 각 후보에 근거 자료가 달린 가치 분석 보고서를 만든다.
- 투자 판단은 투자심의(제안 → 상호 비판 → 리스크 검토 → 표결)를 거친 것만 조언으로 낸다.
- 분야가 다른 전문가 운용역 5명이 각자 가상 포트폴리오를 운용하고, 성과를 같은 기준으로 비교해 어느 관점을 얼마나 믿을지 데이터로 정한다.
- 실제 포트폴리오의 집중도, 손실 한도, 변동성을 상시 점검하고 한도를 넘으면 경보를 보낸다.

## 범위 밖 (Non-goals)

- **자동 주문 실행.** 시스템은 조언과 경보만 낸다. 실제 매매는 사용자가 직접 한다. 증권사 API는 조회 기능만 구현한다.
- 다른 사람에게 자문을 제공하거나 판매하는 것. 그렇게 하면 투자자문업 등록 대상이 된다. 본인 전용으로만 쓴다.
- 초단타(초·분 단위) 매매 신호. 판단 주기는 수 분 이상이다.
- 파생상품, 레버리지, 공매도 전략. 1차 범위는 현물 주식과 ETF다.
- 국내·미국 외 시장.

## 사용자 / 사용 시나리오

사용자는 본인 한 명이다.

1. **아침 브리핑 (07:30):** 밤사이 미국장 결과, 보유 종목 관련 뉴스와 공시, 오늘 일정(실적 발표, 경제지표)을 메신저로 받는다.
2. **장중 경보:** 보유 종목에 악재 공시가 뜨면, 공시 요약과 영향 판단, 리스크 담당의 권고(유지·축소·관찰)를 바로 받는다.
3. **종목 발굴:** 발굴 담당이 SNS 언급 급증과 실적 개선 공시를 함께 잡아낸 종목을 후보로 올린다. 가치 분석 보고서가 붙고, 다음 투자심의 안건이 된다.
4. **투자심의 (16:00 국내, 22:00 미국, 또는 긴급 소집):** 운용역 5명이 후보와 보유 종목에 의견을 낸 뒤 서로의 의견을 비판한다. 리스크 담당이 한도를 검토하고 표결한다. 사용자는 회의록과 결론을 받는다.
5. **주간 성과 리뷰:** 운용역별 가상 포트폴리오의 수익률, 최대 낙폭, 적중률 순위와 실제 포트폴리오와의 차이를 받는다.
6. **질문:** "지금 반도체 비중 줄여야 해?"라고 물으면 현재 데이터와 운용역들의 의견을 모아 답한다.

## 에이전트 구성

### 운용역 5명 (경쟁 참가, 표결권 있음)

모든 운용역은 **비판적 태도**를 기본으로 한다. 자기 분야의 근거로 판단하고, 다른 운용역의 의견에서 약점을 찾아 반박해야 한다. 근거 없이 동의하는 것은 허용하지 않는다.

| # | 운용역 | 전문 분야 | 주로 보는 데이터 | 다른 운용역에게 던지는 전형적 비판 |
|---|---|---|---|---|
| 1 | 거시경제 전문가 | 금리, 환율, 경기 사이클, 정책, 자산 배분 | 경제지표, 중앙은행 발표, 환율, 국가·섹터 비중 | "개별 종목이 좋아도 금리 인상기에는 밸류에이션이 깎인다" |
| 2 | 기업가치 전문가 | 재무제표, 이익의 질, 밸류에이션 | 공시, 재무 데이터, 동종 기업 비교 | "주가는 올랐지만 현금흐름이 따라오지 않는다" |
| 3 | 산업·기술 전문가 | 산업 구조, 경쟁 구도, 기술 변화, 공급망 | 산업 뉴스, 경쟁사 실적, 공급망 공시 | "숫자는 좋지만 경쟁사 신제품에 점유율을 뺏길 구조다" |
| 4 | 수급·차트 전문가 | 가격 추세, 거래량, 외국인·기관 수급, 옵션 만기 | 시세, 수급, 공매도 잔고 | "펀더멘털과 별개로 지금은 매물대에 막혀 있다" |
| 5 | 이벤트·심리 전문가 | 뉴스, SNS 여론, 공시 이벤트, 실적 발표 반응 | 뉴스, SNS 언급량과 감성, 일정 | "이미 모두가 아는 호재라 주가에 반영됐다" |

### 진행·통제 역할 (경쟁 불참, 표결권 없음)

| 역할 | 하는 일 |
|---|---|
| 발굴 담당 | 신호를 점수화해 종목 후보를 만들고 심의 안건으로 올린다 |
| 분석 담당 | 후보마다 가치 분석 보고서를 만든다 |
| 리스크 담당 | 표결 전에 한도(집중도, 손절선, 최대 낙폭, 환율 노출)를 검토한다. 한도를 어기는 안건은 거부권을 가진다. 한도 계산은 코드가 하고, 리스크 담당은 그 결과를 해석한다 |
| 심의 의장 | 안건 진행, 발언 순서, 비판 라운드 관리, 회의록 작성. 의견을 내지 않는다 |

## 핵심 기능

### 감시 (24시간)

- [ ] 뉴스 수집: 국내외 경제 뉴스 RSS와 뉴스 API. 종목과 테마에 연결하고 중복 기사를 묶는다.
- [ ] 공시 수집: 국내 DART, 미국 SEC EDGAR. 공시 유형별 중요도를 매긴다(유상증자, 최대주주 변경, 실적, 소송 등).
- [ ] SNS·커뮤니티 수집: 종목 언급량, 감성, 급증을 측정한다. 출처별 신뢰도를 따로 둔다.
- [ ] 시세 감시: 가격, 거래량, 수급(외국인·기관) 이상을 탐지한다. 국내장, 미국장, 시간외 거래를 포함한다.
- [ ] 일정: 실적 발표, 배당, 경제지표, FOMC 같은 이벤트 달력.

### 분석

- [ ] 종목 발굴: 여러 신호(뉴스, 공시, SNS, 수급, 가격)가 겹치는 종목을 점수화해 후보 목록을 만든다.
- [ ] 가치 분석 보고서: 사업 요약, 재무(성장성, 수익성, 부채), 밸류에이션(PER, PBR, EV/EBITDA, 동종 비교), 촉매와 리스크, 근거 링크.
- [ ] 이벤트 영향 분석: 공시나 뉴스 한 건이 보유 종목에 주는 영향을 판단한다.

### 투자심의와 경쟁

- [ ] 투자심의 절차:
  1. 안건 상정 (의장)
  2. 1차 의견: 운용역 5명이 서로의 의견을 보지 않고 각자 의견(매수·매도·유지, 비중, 근거, 확신도)을 낸다.
  3. 상호 비판: 각 운용역이 다른 운용역의 의견 중 가장 약한 근거를 골라 반박한다.
  4. 재반론과 수정: 반박받은 운용역이 방어하거나 의견을 수정한다.
  5. 리스크 검토: 리스크 담당이 한도를 검토하고, 위반하면 거부한다.
  6. 표결: 성과 기반 가중치를 적용한다.
  7. 회의록: 결론, 소수 의견, 결론을 뒤집을 조건(무엇이 일어나면 다시 심의할지)을 기록한다.
- [ ] 가상 포트폴리오: 운용역마다 같은 초기 자금으로 국내·미국 종목을 가상 운용한다. 거래 비용, 세금, 환율을 반영한다.
- [ ] 성과 평가: 운용역별 수익률, 최대 낙폭, 샤프 비율, 적중률. 성과에 따라 심의 표결 가중치를 조정한다.

### 리스크 관리

- [ ] 실제 포트폴리오: 증권사 API로 국내·해외 주식 잔고를 조회한다.
- [ ] 한도 점검: 종목·섹터·국가 집중도, 손절선, 포트폴리오 최대 낙폭, 현금 비중, 달러 자산 비중.
- [ ] 상관관계와 변동성 점검, 시나리오 손실 추정(예: 코스피 -10%, S&P 500 -10%, 원/달러 ±5%).
- [ ] 경보: 한도 초과, 손절선 접근, 보유 종목 악재.

### 전달

- [ ] 메신저 알림(텔레그램 등): 긴급 경보, 아침 브리핑, 심의 결과.
- [ ] 대시보드: 포트폴리오, 운용역 순위, 심의 기록, 종목 보고서.
- [ ] 투자 일지: 사용자의 실제 매매와 그 시점의 심의 의견을 함께 기록한다. 나중에 판단을 복기할 수 있다.

## 기술 구상

- 기술 스택: Python. 에이전트 오케스트레이션은 LLM API(Claude 등)와 도구 호출. 데이터 저장은 PostgreSQL(시계열은 TimescaleDB 등). 작업 예약은 스케줄러와 이벤트 큐.
- 아키텍처:
  1. **수집 계층 (LLM 없음):** 뉴스, 공시, SNS, 시세 수집기가 정해진 주기나 실시간 스트림으로 데이터를 모아 저장한다.
  2. **신호 계층 (규칙과 통계):** 급증, 이상치, 중요 공시 유형을 규칙으로 걸러 "사건"을 만든다. 여기서 걸러진 사건만 LLM으로 넘겨 비용을 줄인다.
  3. **에이전트 계층:** 운용역 5명, 발굴 담당, 분석 담당, 리스크 담당, 심의 의장.
  4. **포트폴리오 계층 (LLM 없음):** 가상·실제 포트폴리오 회계, 환율 환산, 성과 계산, 한도 점검. 숫자 계산은 전부 코드로 한다.
  5. **전달 계층:** 메신저 봇, 대시보드.
- 원칙:
  - 수치(가격, 재무, 수익률)는 데이터에서 코드로 계산한다. LLM은 해석과 토론만 한다.
  - LLM이 낸 모든 주장에는 근거 데이터나 출처 링크를 붙인다. 근거가 없는 주장은 심의에서 제외한다.
  - 작업 성격에 따라 모델을 나눈다. 대량 요약과 분류는 경량 모델, 가치 분석과 심의는 상위 모델을 쓴다.
  - 운용역 사이에 의견 다양성을 확보한다. 분야별로 입력 데이터를 다르게 주고, 필요하면 운용역마다 다른 회사의 모델을 쓴다.
- 증권사 API:
  - 국내와 해외 주식 잔고를 모두 조회할 수 있는 API를 쓴다 (예: 한국투자증권 KIS Developers).
  - **조회 기능만 구현하고 주문 기능은 코드에 넣지 않는다.** 증권사 API 키는 보통 주문 권한도 함께 가지므로, 키는 비밀 저장소에 두고 저장소, 로그, LLM 입력에 넣지 않는다.
- 외부 연동 (후보):
  - 국내 시세와 계좌: 증권사 OpenAPI
  - 국내 공시: DART OpenAPI
  - 미국 공시: SEC EDGAR
  - 미국 시세와 재무: 증권사 해외 시세 API 또는 유료 데이터 API(무료 플랜은 지연 시세)
  - 뉴스: 언론사 RSS, 뉴스 검색 API
  - SNS: X(유료 API), Reddit, 텔레그램 공개 채널. 커뮤니티 수집은 각 서비스 약관을 확인한다.
  - 경제지표와 환율: 한국은행 ECOS, FRED

## 운영 비용 결정 방식

월 비용 상한은 미리 정하지 않고, **비용 시뮬레이션을 거쳐 결정한다.**

1. MVP를 2~4주 운영하면서 항목별 실제 사용량을 기록한다: LLM 호출 수와 토큰(작업별, 모델별), 데이터 API 요금, 서버비.
2. 같은 기간을 설정 몇 가지로 나눠 비교한다: 심의 주기, 운용역 모델 등급, 긴급 심의 소집 기준, SNS 수집 범위.
3. 설정별 월 예상 비용과 얻는 효과(경보 수, 심의 품질)를 표로 정리한다.
4. 사용자가 그 표를 보고 월 상한과 기본 설정을 정한다.
5. 운영 중 비용이 상한에 가까워지면 경량 모델로 내리고, 넘으면 정기 심의만 남긴다.

## 구현 단계 (MVP → 확장)

1. **MVP: 감시와 경보.** 증권사 API로 국내·해외 잔고 조회, DART·SEC 공시와 뉴스 RSS 수집, 중요 사건 요약 알림, 아침 브리핑.
2. **비용 시뮬레이션.** 위 "운영 비용 결정 방식"대로 2~4주 측정하고 월 상한을 정한다.
3. **가치 분석.** 재무 데이터 연동, 종목 보고서 생성, 관심 종목 관리.
4. **투자심의.** 운용역 5명과 리스크 담당, 의장으로 국내·미국 정기 심의, 회의록 생성.
5. **경쟁과 평가.** 운용역별 가상 포트폴리오, 성과 순위, 표결 가중치 조정. 최소 3개월 가상 운용으로 검증한다.
6. **리스크 관리 강화.** 한도 점검, 시나리오 분석, 투자 일지.
7. **확장.** SNS 수집, 긴급 심의 자동 소집, 대시보드.

## 열린 질문 / 리스크

- 운용역 교체 규칙: 성과 하위 운용역을 언제, 어떻게 바꿀지(예: 6개월 연속 최하위면 프롬프트나 모델 교체).
- 표결 가중치 공식: 성과를 어떤 기간, 어떤 지표로 가중치에 반영할지.
- 리스크 한도 값: 종목·섹터·국가 집중도, 손절선, 최대 낙폭, 달러 비중의 구체적인 숫자.
- 긴급 심의 소집 기준: 어떤 사건이면 정기 심의를 기다리지 않을지.
- **LLM 고유 위험:**
  - 환각: 존재하지 않는 공시나 숫자를 만들 수 있다. 출처를 반드시 붙이고, 수치는 코드로 검증한다.
  - 백테스트 오염: LLM은 학습 시점까지의 실제 주가 흐름을 알고 있어서, 과거 데이터로 검증하면 성과가 부풀려진다. 성능 검증은 **앞으로의 가상 운용**으로만 한다.
  - 같은 모델을 쓰는 운용역들은 의견이 비슷해질 수 있다. 분야별 입력 데이터와 모델을 다르게 해 다양성을 확보한다.
  - 비판적 태도를 강제하면 근거 없는 반대가 나올 수 있다. 비판에도 근거를 요구한다.
- SNS 데이터의 조작(펌프앤덤프, 리딩방): 급증 신호만으로 매수 의견을 내지 않게 한다.
- 규제: 본인 전용이면 문제없지만, 결과를 남에게 공유하거나 유료로 제공하면 투자자문업 및 유사투자자문업 규제를 받는다.
- 최종 판단과 책임은 사용자에게 있다. 시스템 의견은 참고 자료다.
